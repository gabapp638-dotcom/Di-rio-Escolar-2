Notificações push confiáveis mesmo com o navegador fechado exigem publicação como PWA e configuração de serviço de notificações. O HTML sozinho não garante esse comportamento. A exportação .ics pode ser importada no calendário do celular/computador.

Configurações e sincronização

Conta e banco de dados na nuvem

Configure um projeto Supabase para ter login e sincronização entre dispositivos. Os campos abaixo guardam a URL e a chave pública (anon/publishable) neste navegador. Nunca coloque uma chave secreta/service_role no HTML.

Nuvem não configurada.

Configuração obrigatória no Supabase

Depois de criar o projeto, abra o SQL Editor do Supabase e execute o SQL abaixo. Ele cria uma tabela privada por usuário e ativa políticas de segurança (RLS).

create table if not exists public.diario_docente_data (
  user_id uuid primary key references auth.users(id) on delete cascade,
  payload jsonb not null default '{}'::jsonb,
  updated_at timestamptz not null default now()
);
alter table public.diario_docente_data enable row level security;
create policy "Cada usuário acessa seus próprios dados"
on public.diario_docente_data for all
using (auth.uid() = user_id)
with check (auth.uid() = user_id);
grant select, insert, update, delete on public.diario_docente_data to authenticated;
Importante: para acesso remoto, hospede este arquivo em HTTPS, configure o Supabase Auth e teste as políticas. O HTML não cria sozinho um projeto Supabase. A chave pública pode ficar no front-end somente com RLS corretamente configurado.

Backup e dados

Faça backup antes de trocar de navegador ou aparelho. Os dados locais não sincronizam automaticamente sem a configuração da nuvem.
